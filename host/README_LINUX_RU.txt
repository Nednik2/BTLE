=====================================================================
  BLE-сниффер на HackRF (BTLE / btle_rx) — Ubuntu/Debian
=====================================================================

ВНИМАНИЕ: на Linux собираем из ИСХОДНИКОВ. Папку build\ и файлы
.exe/.dll из Windows-сборки не используем — они не для Linux.

---------------------------------------------------------------------
0. ПЕРЕНОС ИСХОДНИКОВ
---------------------------------------------------------------------
Скопируй на Ubuntu всю папку BTLE (с подпапками host/, matlab/ и т.д.).
Дальше все команды — из каталога BTLE/host.

Если скрипты переносились с Windows, убери символы возврата каретки:
  sudo apt-get install -y dos2unix
  dos2unix build_ubuntu.sh btle-tools/src/btle_wireshark.sh

---------------------------------------------------------------------
1. СБОРКА (одной командой)
---------------------------------------------------------------------
  cd BTLE/host
  bash build_ubuntu.sh

Скрипт делает:
  - ставит build-essential cmake libhackrf-dev hackrf wireshark
  - кладёт udev-правила 52-hackrf.rules (доступ к HackRF без root)
  - собирает с флагом -std=gnu11
  - бинарник: BTLE/host/build/btle-tools/src/btle_rx

ПОСЛЕ сборки ПЕРЕВОТКНИ HackRF в USB — иначе udev-правила не применятся.

Ручная сборка (если без скрипта):
  sudo apt-get install -y build-essential cmake libhackrf-dev hackrf wireshark
  cd BTLE/host
  cmake -S . -B build -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DCMAKE_C_FLAGS=-std=gnu11
  cmake --build build -j

---------------------------------------------------------------------
2. РАЗРЕШЕНИЯ
---------------------------------------------------------------------
Захват в Wireshark без root (Ubuntu спросит при установке — ответь «Да»):
  sudo usermod -aG wireshark $USER
Затем ПЕРЕЛОГИНЬСЯ (или reboot), иначе группа не применится.

Проверка связи с прибором:
  hackrf_info
Если "Access denied" — не применились udev-правила: перевоткни HackRF,
либо запусти через sudo.

---------------------------------------------------------------------
3. ЖИВОЙ ПРОСМОТР В WIRESHARK
---------------------------------------------------------------------
  cp btle-tools/src/btle_wireshark.sh build/btle-tools/src/
  chmod +x build/btle-tools/src/btle_wireshark.sh
  cd build/btle-tools/src
  ./btle_wireshark.sh [канал] [LNA] [VGA]

  канал — 37/38/39 (по умолч. 37)
  LNA   — 0..40 шаг 8 (по умолч. 16)
  VGA   — 0..62 шаг 2 (по умолч. 20)

Примеры:
  ./btle_wireshark.sh
  ./btle_wireshark.sh 38 24 20
  ./btle_wireshark.sh 37 16 20 -o      (-o и прочие ключи btle_rx — в конце)

Как работает: скрипт создаёт FIFO в /tmp, запускает Wireshark на чтение,
затем btle_rx пишет туда pcap. На Linux ПЕРВЫМ стартует Wireshark
(в отличие от Windows).

ОСТАНОВКА: Ctrl+C в терминале. Скрипт сам закроет Wireshark и удалит FIFO.

---------------------------------------------------------------------
4. ЗАПИСЬ В ФАЙЛ
---------------------------------------------------------------------
  cd build/btle-tools/src
  ./btle_rx -c 37 -l 16 -g 20 -s capture.pcap
Ctrl+C для остановки, затем:  wireshark capture.pcap

---------------------------------------------------------------------
5. ПОДБОР УСИЛЕНИЯ
---------------------------------------------------------------------
  Пакетов мало/нет            -> поднимай LNA: 16 -> 24 -> 32
  Прибор вплотную к источнику -> снижай: LNA 0..8, VGA 10..20
  Много "Malformed"           -> перегрузка, снизь усиление
Число пакетов скачет между запусками — это нормально (эфир нерегулярный).

---------------------------------------------------------------------
6. ФИЛЬТРЫ В WIRESHARK
---------------------------------------------------------------------
  !_ws.malformed                                 — скрыть битые
  btle.advertising_address == aa:bb:cc:dd:ee:ff  — одно устройство
  btle.advertising_header.pdu_type == 0x00       — только ADV_IND
  btcommon.eir_ad.entry.device_name              — пакеты с именем

---------------------------------------------------------------------
7. ЧТО ВИДНО
---------------------------------------------------------------------
Каналы 37/38/39 — только рекламные пакеты (маячки): MAC, тип, имя,
данные производителя. Содержимое соединений (клавиатуры, наушники)
НЕ видно: после сопряжения оно шифруется и прыгает по 37 каналам данных.

---------------------------------------------------------------------
8. ЕСЛИ НЕ РАБОТАЕТ
---------------------------------------------------------------------
"bad interpreter: No such file or directory"  -> dos2unix на .sh (см. п.0)
Прибор занят / зависло                        -> pkill btle_rx
"cmake ... policy version"                    -> флаг уже в командах выше
Wireshark не открывает FIFO                   -> добавь себя в группу
                                                  wireshark и перелогинься
